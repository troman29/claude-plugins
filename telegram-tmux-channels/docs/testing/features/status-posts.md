# Feature: status-posts (PerTurnEditablePost)

**Цель.** ОДИН самообновляемый пост на биндинг за ход, секциями: подагенты (🤖 Агенты), задачи
(📋 Задачи, `TaskCreate`/`TaskUpdate`), тудушки (📝, `TodoWrite`), фоновые шеллы (⚙️ Фоном,
`Bash` с `run_in_background`), вызовы `Skill`. Готовые элементы остаются с ✅ (пост = история
хода, не только снапшот). Пост шлётся ОДИН раз (msgId=-1 резервирование), дальше редактируется
на месте; новый ход = новое сообщение внизу. Смысл одного поста — одно уведомление на ход
вместо пяти.

**Код.** `PerTurnEditablePost` (send-once→edit, reservation guard) + `beginStatusBatch`/`pushStatus`
+ `statusState` в `hub.ts`; чистый рендер — `src/status-render.ts` (`tests/status-render.test.ts`);
события — `subagent-hook.ts` → hub.

**Границы.** У фонового шелла нет хука завершения — строка живёт до конца батча. Агенты воркфлоу
(`workflow-subagent`) в этот пост не идут: их статус — отдельное сообщение из скрейпа пейна
(`parseWorkflow`).

**Предусловие.** Контейнер, живая сессия, хуки плагина засижены (в контейнере — entrypoint).

---

## Позитив

**SP1. 🎯 TaskCreate/TaskUpdate → один самообновляемый пост, без дублей.**
- Шаги: агент делает `TaskCreate` (3 задачи) и `TaskUpdate` (одну → done).
- Ожидаемо: ОДНО сообщение с секцией 📋, редактируется на месте; выполненная — с ✅.
- Fail-режим: N сообщений на N обновлений (double-send race).
- Смотреть: API (кол-во сообщений = 1, текст обновляется), `screenlog.jsonl`.

**SP2. Подагенты → секция 🤖 в том же посте.**
- Шаги: агент запускает Task-субагента.
- Ожидаемо: статус агента 🟡→✅ по завершении, без нового сообщения.

**SP3. Skill-вызов → секция 🧩 в том же посте.**

**SP6. Фоновый Bash → секция ⚙️.**
- Шаги: `Bash` с `run_in_background: true`.
- Ожидаемо: строка ▶️ с description (или командой) в общем посте; обычный Bash — ничего.

## Негатив / швы

**SP4. Новый ход → новое сообщение (не дописывает старое).**
- Шаги: два отдельных хода с задачами.
- Ожидаемо: у каждого хода свой пост (turnEnded → fresh).

**SP5. Субагент + задачи + скилл в одном ходу → ОДИН пост со всеми секциями.**
- Ожидаемо: одно сообщение, секции в порядке агенты → задачи → тудушки → фон → скиллы.
- Fail-режим: несколько сообщений (регрессия к старой модели четырёх постов).

**SP7. Живой фоновый агент не закрывает батч.**
- Шаги: запустить `run_in_background`-агента, дождаться конца хода (Stop), запустить второго.
- Ожидаемо: оба в ОДНОМ посте — новый пост открывается, только когда ход кончился И живой
  работы нет (иначе первый агент был бы брошен в заменённом сообщении).
