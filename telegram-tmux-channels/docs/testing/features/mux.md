# Feature: mux (мультиплексор агентов)

**Цель.** Все агенты живут в одном мультиплексоре: в tmux — окнами общей сессии `agents`, в herdr —
workspace'ами одной сессии herdr. Хаб видит только интерфейс `Mux` (`src/mux/`): создать, найти и
погасить окно биндинга по имени, писать и читать пейн по непрозрачному id. Бэкенд выбирает
`TELEGRAM_MUX=tmux|herdr`, по умолчанию tmux. Сессии прежней схемы (сессия на биндинг) переезжают
окном в `agents` при первом обращении, без перезапуска агента.

**Код.** `src/mux/{types,tmux,herdr,index}.ts`, обёртки в `src/tmux-ops.ts`, `prestartTarget` и чистилка
тика в `hub.ts`, пейн стаба в `stub.ts`.

**Предусловие.** Харнесс `claude-tmux`, топики 3 и 129 (`sandbox`), в образе tmux и herdr.

## Юниты ✅
`tests/mux.test.ts`: id пейна против предстартовой цели (оба бэкенда), пейн стаба из `TMUX_PANE` или
`HERDR_PANE_ID`, перевод клавиш хаба в имена herdr.

## Позитив (оба бэкенда)

**MX1. Подъём новой сессии.** Сообщение в незапущенный топик.
- Ожидаемо: tmux — окно с именем биндинга в сессии `agents`, имя не меняется на `claude`; herdr —
  workspace с этой меткой. Стаб подключился с id пейна, ответ пришёл в топик.
- Смотреть: `tmux list-windows -t agents` / `herdr workspace list`, hub-лог `subscribe … pane=`.

**MX2. Два топика одновременно.** Сообщения в 3 и 129 подряд.
- Ожидаемо: два окна в одной сессии, ответы в свои топики.

**MX3. Экраны до старта.** Доверие папке / хукам Codex на свежем пейне.
- Ожидаемо: авто-ответ по `prestartTarget`, стаб подключается.

**MX4. `/screen` и `/tui`.** Цветной PNG и текстовый дайджест; кнопки `/tui` (стрелки, Esc, Ctrl-C).

**MX5. Пикер.** AskUserQuestion → кнопки → выбор доходит до агента.

**MX6. `/restart`, `/restart_all`, `/close`, подъём после простоя.** Окно живёт, агент перезапущен
или погашен, повторный подъём идёт в то же окно.

**MX7. `/unbind` и `/delete`.** Окно (workspace) погашено вместе с процессами, остальные целы.

## Швы и fault-injection

**MX8. Перенос старой сессии.** `[СПЕЦ]` До старта нового хаба поднять сессию прежней схемы (`tmux
new-session -s <имя>` с живым агентом). Ожидаемо: при первом обращении окно переехало в `agents`, имя
окна = имя биндинга, агент тот же (pid не сменился).

**MX9. Рестарт хаба в середине хода.** Агенты не погибли, стабы переподключились.

**MX10. Нет сессии `agents` / нет сервера herdr.** Первый подъём создаёт её сам; `kill-server` / `herdr
server stop` между ходами — следующий подъём создаёт заново.

**MX11. Последнее окно закрыто.** Сессия `agents` исчезает; следующий подъём создаёт её заново.

**MX12. Подключение человека.** tmux: `attach -t agents` с узким терминалом — размер окон агентов не
меняется (`window-size manual`).

## Лог прогона

**2026-10-20, Docker + MTProto, tmux 3.4, herdr 0.9.5.** tmux: MX1, MX2, MX3 (авто-ack по `=agents:=имя`), MX4
(`/screen` PNG, `/tui`), MX6 (`/restart`), MX7 (`/unbind`), MX8 (перенос: тот же pid шелла, имя закреплено),
MX10 (с пустого сервера), MX12 (клиент 80 колонок — окна 200×100). herdr: MX1, MX2, MX4 (`/screen`), MX6, MX7,
MX10, рестарт хаба (стабы переподключились к тем же пейнам), три цикла рестарта сервера herdr без дублей.
Найдено и исправлено четыре бага — `regression-checklist.md` за 2026-10-20. Не прогнаны: MX5 (пикер) и MX9
(рестарт посреди хода) — пейн-адресация у них та же, что у `/tui` и подъёма.
